# BuildStream Resources

## Knowledge

- [BuildStream documentation](https://docs.buildstream.build/)
  Canonical manual (stable 2.8 + `master`). Use for: project format, element
  kinds, CLI, caches, architecture. The first stop for any fact.
- [apache/buildstream](https://github.com/apache/buildstream)
  Source and release notes. Use for: exact behaviour, NEWS/changelog, plugin API.
- [BuildStream website](https://buildstream.build/)
  The "why" and the list of real users. Use for: framing BuildStream against
  other tools.
- [freedesktop-sdk](https://gitlab.com/freedesktop-sdk/freedesktop-sdk)
  The base stack frameless sits on. Use for: what components exist and how the
  runtime is assembled.
- [gnome-build-meta](https://gitlab.gnome.org/GNOME/gnome-build-meta/)
  The desktop layer and plugin junctions. Use for: GNOME composition and
  `collect_initial_scripts`.
- Local worked examples: `~/Projects/dakota`, `~/Projects/fsdk-containers`,
  `~/Projects/server`. Use for: how a real BuildStream OS image is wired.
- `docs/research/02-buildstream.md`, `docs/research/03-projectbluefin-buildstream.md`
  Our own condensed notes. Use for: a fast orientation before the primary docs.

## Wisdom (Communities)

- [Universal Blue Discord](https://discord.gg/WEu6BdFEtp)
  Use for: Bluefin/dakota context and real-world image-building questions.
- [apache/buildstream issues](https://github.com/apache/buildstream/issues)
  Use for: checking whether a behaviour is known or intended.

## Gaps

- No dedicated BuildStream user community identified yet (the project moved from
  GitLab to Apache; discussion venues are worth confirming).
- No hands-on tutorial beyond the upstream "first project" walkthrough.
